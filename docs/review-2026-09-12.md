# Current-state review, 2026-09-12

Reviewed main at `cde1b09`, including recent sync batching, deletion, persistence,
assistant, SSH/terminal, and native accessibility work. Eleven confirmed defects
were repaired with regressions that reproduced the affected behavior.

| Area | Failure | Repair |
|---|---|---|
| Credential sync | An unchanged server sharing a credential could stamp it older than an edit, causing the next sync to restore the old password. | Collect each shared secret once using its newest participating server timestamp. |
| Snippet sync | A record whose payload named a different snippet could bypass that snippet's conflict resolution and overwrite it. | Require the envelope and payload to identify the same snippet. |
| Sync enrollment | Two servers sharing a credential caused it to be re-encrypted twice, with the second read using the old key. Enrollment failed and the credential became unreadable. | Read each distinct credential before rewriting any of them. |
| Persistence | Concurrent saves shared one temporary path and could rename or delete one another's files. | Serialize snapshots by normalized destination path; preserve the destination when a POSIX rename fails. |
| Assistant remount | Reopening the sidebar reused a paste callback owned by its destroyed widget, silently dropping staged commands. | Bind the terminal target to each send. |
| Assistant reset | A reply arriving after New chat could stage a command into the next conversation's terminal and repopulate cleared provider history. | Invalidate pending turns at reset/disposal and check before tool dispatch, history updates, and controller adoption. |
| Assistant context | Previously shared terminal output remained in history and was resent even after Include terminal output was disabled. | Attach terminal snapshots only to requests within the turn that shared them. |
| Terminal context | The final column of the last row was missing from recent terminal text. | Use the buffer's exclusive end coordinate. |
| Terminal replies | Responses to remote status queries consumed one-shot Ctrl and marked an empty prompt as having user input. | Forward device replies without treating them as keystrokes. |
| Cursor reports | Cursor reports used zero-based coordinates and ignored origin mode's scrolling margin. | Emit one-based coordinates relative to the active origin. |
| Closed terminals | A shell finishing its handshake after its tab closed could feed output into disposed notifiers. | Ignore input and remote output after terminal disposal. |

Cursor-report behavior was checked against the
[XTerm control sequence reference](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html).

## Verification

- All three pure-Dart packages analyze cleanly; 661 tests pass.
- Flutter app analysis is clean; 506 tests pass. Two Linux procfs permission
  fixtures are skipped on macOS and are exercised by Linux CI.
- Enrollment regressions cover registration/login and reading shared
  credentials after restarting services.
- Persistence regressions cover overlapping snapshots, concurrent host-key
  approvals, and a successful save after a failed write.
- Assistant regressions cover sidebar remount, reset during provider/search
  waits, preventing stale paste actions, preserving new conversation history,
  and withholding earlier terminal snapshots from later turns.
- Terminal regressions cover final-column extraction, device replies, disposed
  engines, cursor home/positioning, wrap boundaries, and scrolling margins.
- The native macOS accessibility lifecycle fixture passes against the cached
  release engine with graphics access. It does not launch the Dart app or use
  saved user data.
- A local macOS release build succeeds; the app was not installed or launched.
- The vendored terminal suite passes 167 tests. Two pre-existing macOS-only
  text-scaling goldens still fail (302 and 601 differing pixels). An isolated checkout of
  `cde1b09` with the same dependency lockfile produces identical differences.
  The golden files are unchanged.

## Remaining limits

Vault rekeying still lacks a transaction spanning the vault file and the OS
keychain. Reading all credentials first fixes duplicate references and avoids
partial conversion on a read failure; interruption or failure during the later
writes can still leave those stores out of step. Crash recovery needs a separate
migration protocol and is not solved by this patch.

The existing unsealed-tombstone trust limitation and other product follow-ups
remain documented in [STATUS.md](STATUS.md). This review is not a proof that all
remaining code is defect-free. Live SSH-server, mobile-device, and GUI behavior
outside the automated fixtures was not exercised during this review.
